# 金大师双端履约流程审计

## 范围

- 用户端：询价、报价确认、订单验收、资料维护与订单历史。
- 管理端：待报价、待派单、施工中、待验收、验收问题与返修。
- 目标：检查字段口径、订单示例、状态迁移、操作权限和移动端呈现是否一致。

## 审计结论

初始原型的主要断点是管理端提交报价后越过客户确认直接进入派单，以及客户验收不通过后没有可执行的返修回流。另有用户端与管理端订单号/状态不一致、缺少上门地址和预计工期、用户端历史残留旧修复类型等问题。

本轮已统一主流程：

`客户提交询价 -> 管理端报价 -> 客户确认报价 -> 管理端按确认等级人数选择具体师傅 -> 施工 -> 客户验收 -> 完成或返修 -> 再次验收`

## 已修复

1. 管理端报价提交后保持在“待报价”总 Tab 内，子状态改为“待客户确认”；客户确认前不显示派单入口。
2. 用户端“我的”增加待确认报价，展示维修费、上门费、合计、报价说明与确认动作。
3. 用户端和管理端统一报价单及三张待验收单的订单号、客户、材质、类型、时间和师傅姓名。
4. 用户询价与资料维护增加上门地址；管理端详情增加预计工期和上门地址。
5. 客户验收通过后从待验收 Tab 移除，并同步更新订单历史状态。
6. 客户验收不通过时，图片/视频和问题说明维持必填；管理端验收页显示凭证与问题说明。
7. 管理端“安排返修”会移除待处理问题，将订单送回“施工中”，保留原执行师傅与返修原因；返修完成后再次进入“待验收”。
8. 用户端历史中的旧“断裂”示例改为当前修复类型“裂缝”；宣传单价格表原文中的“断裂”保持不变。

## 运行验证

- 用户端报价确认：状态由“待确认”变为“待派单”，订单历史同步更新，确认按钮禁用。
- 管理端提交报价：状态变为“待客户确认”，待派单数量不增加。
- 管理端派单：金牌大师 2 位订单必须选择恰好 2 名金牌师傅，完成后进入施工中。
- 管理端完工：施工中数量减少、待验收数量增加。
- 用户端验收通过：待验收订单从 3 单变为 2 单，自动切换下一单。
- 用户端验收不通过：问题区自动展开，空提交时上传凭证和问题说明同时标红。
- 管理端返修：待处理问题从 2 单变为 1 单，施工中数量增加；返修完成后再次进入待验收。
- 双端控制台未出现错误；使用 390px 宽隔离视口复测，新增字段、状态卡片和底部导航无横向溢出。

## 边界

当前仍是静态 HTML 高保真原型，双端使用一致的数据合同和可演示状态迁移，但没有后端、数据库、登录、真实上传、消息通知与跨端实时同步。正式微信小程序需要用服务端订单状态机承接这些已确认的界面逻辑。
